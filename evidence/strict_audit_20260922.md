Признаки: `axis_features_20260921.csv`, 160 строк, 100 сигналов, 60 мейнстримов. Строгая проверка: сырые ответы `data/interim/raw/techcrunch/`. Счётчики: `data/interim/collector/cache/counters/`. Сети нет.

Модель: логистическая регрессия, class_weight=balanced, нормировка внутри области, StratifiedGroupKFold k=5, 10 повторов, random_state=42.

## 1. Строгий пересчёт рыночного счётчика

**Чего сделать нельзя.** У всех 1120 сохранённых ответов TechCrunch `per_page=1`: на пару (фраза, окно) лежит ровно один документ, а не вся выдача. Пересчитать n_market строго — «сколько из n документов содержат фразу» — по кэшу невозможно: остальных n−1 документов в нём нет. Для точного пересчёта нужна сеть: `per_page=100` с постраничным обходом.

**Что считается точно.** По каждому окну проверяется тот один документ, что сохранён: содержит ли он искомую фразу целиком (регистр и дефисы сняты). Отсюда k_sampled — сколько окон периода вернули документ, k_strict — в скольких из них фраза есть, has_market_strict — есть ли хоть одно попадание.

**Что оценивается.** n_market_strict_est = n_market × k_strict/k_sampled переносит долю попаданий с выборки из ≤ 6 документов на весь счётчик. n_market_verified — сумма счётчиков только тех окон, где документ фразу содержал. Обе величины — оценки, не пересчёт.

## 4. Честные метрики: порог подобран только на обучающей части

CV: во внешнем фолде порог выбирается внутренней кросс-валидацией на обучающей части, отложенные строки в выборе не участвуют; метрики — среднее ± std по повторам. LOAO: порог выбирается на пяти обучающих областях и применяется к шестой; метрики — среднее по шести областям. Критерий выбора порога — accuracy.
