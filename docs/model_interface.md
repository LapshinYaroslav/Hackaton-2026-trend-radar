# Модель: что вызывать и что придёт в ответ

Короткое описание для интерфейса. Подробности методологии — в `docs/methodology.md`,
числа качества — в `evidence/model_release_20260922.md`.

## Что вызывать

```python
from model.predict import explain

answer = explain(features, area)
```

`features` — словарь из шести чисел, `area` — строка с названием области. Артефакт
читается с диска один раз и дальше держится в памяти, отдельно загружать не нужно.

Если нужна только вероятность и разбор по признакам, без порога и оформления:

```python
from model.predict import predict
probability, contributions = predict(features, area)
```

## Шесть признаков

| имя | что это |
|---|---|
| `volume` | объём документов о технологии |
| `growth_research` | рост научных публикаций против фона источника |
| `recency` | свежесть документов |
| `share_news_wordmatch` | доля новостей, найденных по словам названия, среди всех документов |
| `share_prev6` | доля документов предыдущей шестилетки |
| `age_first_arxiv` | годы от первого препринта arXiv до даты среза |

Пропуск передаётся как `None` — это нормально, у `age_first_arxiv` его нет у 43 %
технологий. Модель подставит медиану обучающей выборки, а вклад признака в ответе
покажет, насколько это сдвинуло результат.

Старое имя `share_market` тоже принимается: оно переименовано, но алиас оставлен.

Незнакомая область работает: для неё берутся общие центр и масштаб вместо
областных. Ответ при этом отличается от ответа для известной области — это
не ошибка, признаки нормируются внутри области.

## Как читать поля

- `score` — вероятность того, что технология слабый сигнал. Относится к задаче с
  уравненными классами, а не к наблюдаемой доле сигналов: читать её как «шанс выше
  базовой доли» нельзя, сравнивать с `threshold` — можно.
- `is_signal` — это и есть `score >= threshold`.
- `top_features` — три самых весомых признака, отсортированы по модулю вклада.
  `contribution` в единицах логита: плюс сдвинул к сигналу, минус — от него.
  Сумма вкладов всех шести признаков плюс свободный член даёт логит, а сигмоида
  от него — `score`. По умолчанию возвращается три признака, `explain(..., top=6)`
  вернёт все.
- `explanation_ru` — готовая строка для показа пользователю.

## Признаки кандидата: название → шесть чисел

Передавать готовые числа больше не нужно. Есть функция, которая соберёт их сама:

```python
from model.candidate import candidate_features

answer = candidate_features("edge model compression", area="Edge")
answer["features"]   # шесть чисел в порядке model.config.FEATURES
answer["counters"]   # окно -> источник -> число документов
answer["sources"]    # какие источники ответили
answer["complete"]   # False, если счётчиков не нашлось
```

Внутри: сборка булева запроса из терминов, счётчики по семи окнам из трёх
источников (OpenAlex, arXiv, TechCrunch), поправка на рост корпуса по
зафиксированным итогам `evidence/source_totals_training.json` и те же функции
расчёта, что считали обучающую таблицу. Расхождение путей ловится тестом
`tests/model/test_candidate.py::test_matches_training_table_on_every_technology`:
для каждой технологии обучающей выборки функция обязана дать ровно те же числа,
что лежат в таблице обучения, с допуском 1e-9.

По умолчанию счётчики читаются из файлового кэша, без сети. В режиме запроса
передаётся `fetch` — функция, которая берёт `SearchTerms` и возвращает счётчики
из живых источников:

```python
candidate_features("photonic inference accelerator", fetch=my_collector_fetch)
```

## Запрос → ранжированный список

```python
from model.ranking import rank_candidates

rank_candidates(["edge model compression", "humanoid robot"], area="Edge")
```

Принимает названия строками или словарями `{"name", "terms", "context_terms", "area"}`.
Возвращает список, отсортированный по убыванию `score`. Кандидаты, у которых
счётчиков не нашлось, не выбрасываются: они уходят в конец с `score: null` и
заполненным `skipped_reason` — интерфейсу надо показать, почему их не оценили.
`limit` режет только посчитанных.

Ссылки на документы модель не добывает: она видит одни числа. Они принимаются
параметром `documents` (имя кандидата → список документов) и кладутся в ответ
как есть.

## Область кандидата: два режима и разные метрики

Признаки нормируются **внутри области**: у каждой из шести областей свои центр
и масштаб, посчитанные по обучающей выборке. Одно и то же значение признака
означает разное в разных областях, поэтому область важна.

Пользователь выбирает одну из шести или «другое»:

```python
from model.config import OTHER_AREA        # "другое"
from model.ranking import known_areas, rank_candidates

known_areas()
# ['Edge', 'Защита ИИ', 'Индустриальный ИИ', 'Инфраструктура ИИ', 'Роботы', 'Финтех']

rank_candidates(names, area="Edge")        # основной путь
rank_candidates(names, area=OTHER_AREA)    # откат
```

Автоматического определения области нет и не будет: проверить такой
классификатор не на чем.

В ответе каждого кандидата два поля говорят, каким путём он посчитан:

| поле | значение |
|---|---|
| `area_known` | `true` — область из шести, `false` — «другое», пустая или любая другая |
| `normalization` | `"по области"` или `"общая (откат)"` |

**«Другое», пустая строка и любое незнакомое название — один и тот же путь:**
берутся общие центр и масштаб по всем 160 строкам обучения. Ошибки не будет,
но ответ отличается от ответа для известной области.

### Какие метрики заявлять

Это разные режимы, и числа у них разные. Полностью — в
`evidence/fallback_mode_20260922.md`, порог во всех строках подобран внутренней
кросс-валидацией на обучающей части.

Кросс-валидация, среднее ± std по 10 повторам:

| режим | AUC | Precision | Recall | F1 | Accuracy |
|---|---|---|---|---|---|
| `area_known: true` | 0.805 | 0.764 ± 0.015 | 0.787 ± 0.043 | 0.775 ± 0.025 | 0.715 ± 0.027 |
| `area_known: false` | 0.791 | 0.752 ± 0.022 | 0.772 ± 0.020 | 0.762 ± 0.014 | 0.698 ± 0.020 |

Leave-one-area-out, среднее по шести областям — ближе всего к тому, что увидит
жюри на незнакомой теме:

| режим | AUC | Precision | Recall | F1 | Accuracy |
|---|---|---|---|---|---|
| `area_known: true` | 0.811 | 0.817 | 0.763 | 0.779 | 0.738 |
| `area_known: false` | 0.821 | 0.771 | 0.812 | 0.783 | 0.726 |

Откат по кросс-валидации хуже на 0.014 AUC и 0.017 Accuracy. На
leave-one-area-out картина неоднородна: AUC у отката выше (0.821 против 0.811),
Accuracy ниже (0.726 против 0.738) — ранжирует он не хуже, а порог на нём
ложится хуже. Если в демо область не выбрана, называть надо вторую строку.

## Чего у модели по-прежнему нет

- **Ссылок на источники** модель не добывает: документы собирает сборщик,
  модель кладёт их в ответ как есть.
- **Текстовых объяснений** сверх `explanation_ru` модель не генерирует.
- **Записи в таблицу `features`** базы данных нет: в схеме лежит `payload JSONB`,
  формат надо согласовать.
